# シミュレーションとは？

## なぜシミュレーションが必要？

HDL（SystemVerilog）でコードを書いたとき、**実際の回路を作る前に動作を確かめる**ことが重要です。

FPGAへの書き込み（配置配線）には時間がかかり、間違いを修正するのも大変です。シミュレーションなら、コンピュータ上で回路の動作を素早く確認できます。

---

## シミュレーションの仕組み

```
[HDLコード] + [テスト仕様] → [シミュレータ] → [結果・波形]
```

1. **HDLコード**: 設計した回路（例: D-FF、カウンタ）
2. **テスト仕様（spec）**: 「この入力を与えたときにこの出力になるはず」という期待値
3. **シミュレータ（deltasim）**: コードをソフトウェアで実行して動作を確かめる
4. **結果・波形**: PASS/FAIL の判定と、信号の時系列変化（VCD形式）

---

## deltasim とは？

**deltasim** は、このアプリで使う SystemVerilog シミュレータです。

```bash
# テスト実行（コマンドライン）
deltasim test 設計ファイル.sv --spec テスト仕様.yaml --json 結果.json
```

- `--spec`: テスト仕様YAMLファイル（どの入力でどの出力を期待するか）
- `--json`: 結果をJSONファイルに書き出す
- `--vcd`: 波形をVCDファイルに書き出す

---

## テスト仕様（spec）の書き方

```yaml
version: 1
top: and_gate  # テスト対象のモジュール名

clock:
  signal: clk
  period_ns: 10  # クロック周期 10ns

sim:
  cycles: 20     # シミュレーションするクロック数

cases:
  - name: "11_gives_1"   # テストケース名
    inputs:
      - at: 3             # 3クロック目に
        set: {a: 1, b: 1} # a=1, b=1 を入力
    expected:
      - at: 5             # 5クロック目で
        check: {y: 1}     # y=1 を期待
```

---

## PASS / FAIL の判定

シミュレーション後、期待値と実測値が一致すれば **PASS**、違えば **FAIL** です。

```
[PASS] case: 11_gives_1  → y が期待通り 1
[FAIL] case: 00_gives_1  → y が 0 のはずが 1 だった
```

FAILのとき: どのクロック、どの信号で、期待値と実測値が何だったかを確認できます。

---

## 波形（VCD）とは？

**VCD（Value Change Dump）** は信号の時系列変化を記録するファイル形式です。

```
時間（ns）: 0  10  20  30  40  50
clk:        0  1   0   1   0   1
a:          0  0   1   1   0   0
y:          0  0   0   1   0   0
```

これを波形ビューアで視覚的に確認できます（次のレッスン）。

---

## まとめ

- シミュレーションは回路の動作をコンピュータ上で確認する手段
- HDLコード + テスト仕様 → シミュレータ → PASS/FAIL + 波形
- deltasim は spec.yaml でテスト条件を定義し、JSON/VCDで結果を出力する
